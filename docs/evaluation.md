# 評価

Context Resolver（REQ-0002）と長期運用（REQ-0004・REQ-0006）の実測結果。Skill の発火と効果は [Skill の評価](skill-evaluation.md)。数値は `tests/eval_context.py` が生成し、手で書き換えない。

## 方法

- **コーパス**: `tests/fixtures/linkbox`（架空のブックマーク管理アプリ。Docs 10 文書・Task 3・引き継ぎ 1）と、このリポジトリ自身の docs/
- **ケース**: Task 起点 3・コード起点 1・依存が不明なキーワード起点 1・自己適用 2。必要な節（required）と、読んでも無駄でない節（acceptable）を人手で判定した
- **required の判定基準**: そのケースの作業者が判断・実装に必要とする節。ID・リンク・コードパスで辿れない横断的な制約やエンティティ定義も含める（取得機構の限界を隠さない）
- **全文**: Goal と Docs の全文、および進行中 Task と引き継ぎを加えた量。エージェントが context なしで読みうる量の上限
- **取得率**: required のうち選定された割合。**混入率**: 選定（起点の Task 自体を除く）のうち required でも acceptable でもない節のトークン割合
- **トークン**: 推定値（ASCII 4 文字・非 ASCII 1 文字で 1 トークン）。実トークナイザによる値ではない
- **長期運用**: `tests/simulate.py` が 10 種の機能追加・技術判断の変更・作業メモの Docs への移動・引き継ぎを 40 サイクル繰り返した生成物で、最新 Task の context 量を測った（生成物は構造が均質な合成データ）

## 考察

- **トークン削減**: 全文（Goal+Docs+進行中 Task+引き継ぎ）に対して 64〜90% 削減した。長期運用では Docs が 17 倍に増えても context 量は 1.24 倍にとどまり、削減率はプロジェクトが大きくなるほど上がる。一時情報（引き継ぎと作業メモ）は 40 サイクルを通じて約 28 トークンで一定だった（作業メモは Task と一緒に退場する）
- **混入**: 0〜13%。S2 の混入は、広い範囲を `code:` で統治する architecture.md の全体が入るため（統治経路の減衰と下限で抑えているが、統治文書が大きいほど増える）
- **欠落**: Task 起点の欠落はすべて、ID・リンク・コードパスのどれでもつながっていない節だった（横断的なセキュリティ制約・エンティティの定義・同じ文書内の整合性の規則）。語彙の一致で一部は選定または「関連の弱い候補」に出るが、全部は拾えない
- **横断的な制約の置き場**: L1・L2 の欠落のうちセキュリティの節（認可・入力の扱い）は、どの作業でも守る規則である。知識モデルではエージェントが常に読む指示ファイル（CLAUDE.md 等）に1行で置くので、context が取得すべき対象ではない。残る欠落はエンティティの定義と同じ文書内の整合性の規則で、リンクを書き足す運用で補う
- **欠落への対処**: 取得機構を推測で広げると混入が増える。代わりに、Skill は (1) 「目的の状態」の語の定義が選定に無ければ選定済み文書の見出しから探す、(2) 見つけた関係を Task の `refs` や仕様本文のリンクとして書き足す（次回から自動で取得される）、を指示する。横断的な制約は、適用範囲を frontmatter `code:` に書くと統治経路で取得される

## 未達・限界

- トークン数は推定値で、Claude の実トークナイザでの計測はしていない
- 評価ケースは 7 件で、正解集合は作者 1 人の判定。大規模な実プロジェクトでの計測はしていない
- 履歴汚染の検出は言い回しの候補提示で、意味の判断（本当に経緯か）はエージェントに依存する
- 同じ事実を別の文で書いた重複（例: 「30 日」が 4 文書に散在）は段落の類似度では検出できない。試行 2 ではエージェントが context と grep で見つけた
- サブエージェントでの試行は 3 回（同じフィクスチャ）。フックは Claude Code 上での発火を確認しておらず、CLI のフック用モードをテストで確認した
