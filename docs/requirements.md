# 要求

Tri-SSD Core が満たす要求。実現方法は [アーキテクチャ](architecture.md) が受け持つ。

## REQ-0001 知識の分類

Goal・Docs・Tasks（作業メモを含む）・引き継ぎ・CHANGELOG の置き場と判定基準が定義され、文書の種別が配置から機械的に決まる。どの置き場にも寿命の終わりがある。

## REQ-0002 関連知識の取得

Task・ID・文書・コードパスを起点に、読むべきセクションだけを選定できる。

- 選定理由と出所を示す
- トークン予算を指定でき、予算不足で必須の情報を省略するときは明示する
- 依存関係が辿れない起点はキーワード探索で補い、その旨を示す
- 履歴（完了 Task・CHANGELOG）は既定で読まない

## REQ-0003 変更影響の逆引き

コード・設定・文書の変更から、見直すべき Docs のセクションと関係する進行中 Task を特定できる。関連知識の取得と同じ知識グラフを使う。

## REQ-0004 整合性と衛生の検査

参照切れ・ID 重複・履歴汚染の疑い・重複記述・肥大化・完了済み Task を指す計画マーカー・Task の書式不備を検出できる。
作業差分については CHANGELOG の記録漏れ・追記偏重・CHANGELOG の書き換えを検出できる。

## REQ-0005 検証証跡による完了判定

Task の受け入れ条件ごとに検証を実行・記録でき、全条件の最新証跡が PASS で、証跡取得後にコードが変わっていない場合だけ完了にできる。

## REQ-0006 一時情報のライフサイクル

作業中の情報は持ち主（Task）と一緒に退場し、引き継ぎは上書きで1つに保たれる。一時情報が溜まる場所が無い。
git 管理外のローカル領域に個人の引き継ぎを置ける。

## REQ-0007 セッションの継続

新しいセッションの開始時に、Goal・進行中 Task と進捗・引き継ぎ・健全性の要約が自動で得られる。

## REQ-0008 導入と移行

新規プロジェクトの初期化、既存プロジェクトへの導入、旧 Tri-SSD（L0〜L3）からの移行ができる。移行は既定でドライランとする。

## REQ-0009 外部依存なし

通常の利用で外部サーバー・有料 API・追加パッケージを必要としない。

## REQ-0010 エージェントを選ばない導入

Claude Code・Codex・Pi・OpenCode が、1つの正本から導入した同じ Skill と同じ CLI `tri` を使える。

- 導入は1回のコマンドで行い、Skill と CLI は同じ版がそろう。再実行すると同じ状態に収束する
- エージェントごとのプラグイン・拡張としての導入を必要としない
- Skill の本文は特定のエージェントの置換変数・フォルダの形に依存しない
