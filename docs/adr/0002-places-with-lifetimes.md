# ADR-0002 取り締まる仕組みを足さず、置き場を寿命に合わせる

## 状況

実エージェントの試行と自己適用で、次の問題が続けて見つかった。

- 横断的な制約（認可・入力の扱いなど）が context に入らない
- ノートが溜まり続けうる
- 意味のない検証・過剰な検証の懸念
- 書式の不揃い

問題が出るたびに検出・警告の仕組みを足した結果、`note` スキル・ノートの整理候補・依存候補の提示・読み込み記録のフック・着手時点との比較が増えた。試行ではどれも効果を示せなかった（意味のない検証 0 件、依存候補はエージェントが使わず自力で補った）。
根本原因は、情報が「いつ必要になり、いつ不要になるか」と関係ない場所に置かれていたことだった。終わりの無い受け箱にノートを置き、全作業で必要な規則を話題別の文書に置いていた。

## 決定

置き場を寿命と読まれ方に合わせ、取り締まる仕組みは足さない。

- 作業メモは Task ファイルの `## メモ` に置き、Task と一緒に退場させる。受け箱・整理候補・`note` スキルを廃止する
- 引き継ぎは上書きの1つだけにする（`tri handoff`）
- 全作業で守る規則は、エージェントが常に読む指示ファイル（CLAUDE.md・AGENTS.md）に1規則1行で置く
- 検証の目的は「完了時点で、依頼者が全部見なくても目的の状態に達したと判断できる証拠を渡すこと」とする。検証記録は AC ごとに最新の結果だけを残し、着手時点との比較は廃止する
- 依存候補の提示と読み込み記録のフックを廃止する（手順にある `impact --git` と重複していた）
- 書式の正はテンプレートファイル（`templates/`）にする
- 使われていない `graph` コマンドと JSON 出力を廃止する

## 結果

- Skill は 3、フックは 2 になった
- 一時情報が溜まる場所が無くなり、整理の仕組みが要らなくなった
- 依存が書かれていない節（エンティティの定義など）の取りこぼしは残る。見つけたらリンクを書き足す運用で補う
