# Tri-SSD Goal

## 目的

AI エージェント駆動の長期開発で、プロジェクトの知識が陳腐化・肥大化せず、必要な知識だけを低コストで使える状態を保つ。
Tri-SSD は開発手順を強制するフレームワークではなく、知識のライフサイクルとコンテキストを管理するハーネスである。

## 成功状態

- **正確**: 文書は現在または将来のあるべき状態を示し、現在の実装と将来の設計を混同しない。過去の経緯は本文に累積しない
- **持続**: 開発が長期化しても文書が重複・肥大化・陳腐化しない。一時的な情報は整理される
- **効率**: エージェントは作業に必要な情報だけを取得する。必要な制約を欠落させずにトークン消費を抑える
- **自律**: 文書の分類・取得・改訂・整理・整合性検証をエージェントが実行でき、人間が整理し続ける必要がない
- **継続**: セッションやエージェントが変わっても、目的・仕様・現在位置・未完了の作業・検証証跡を引き継げる
- **検証可能**: 作業の完了を自己申告ではなく、あるべき状態を満たした証拠で判定できる

## 原則

- **管理のための管理を増やさない**。ルールや文書を増やすこと自体を目的にしない
- **決定的に処理できることは機械で行う**。意味の判断と文章の改訂はエージェントが行う
- **知識は寿命と更新契機で置き場を決める**

## やらないこと

- チーム向けの知識共有ワークフロー・外部チャット連携・組織向け配布や承認
- 自動 Skill 生成・Web ダッシュボード・独立したサーバー・ベクトル DB
- 将来の用途のためのスタブ・未使用の設定・抽象インターフェース
